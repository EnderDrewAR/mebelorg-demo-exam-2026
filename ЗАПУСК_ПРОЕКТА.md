# Шпаргалка по запуску проекта

## Что должно быть установлено

Перед запуском проверьте:

1. Установлен PostgreSQL 16.
2. Служба PostgreSQL запущена.
3. Пароль пользователя `postgres` равен `postgres`.
4. Установлен `uv`.
5. При первом запуске есть доступ к интернету для загрузки Python-зависимостей.

Проверка `uv`:

```powershell
uv --version
```

Проверка службы PostgreSQL:

```powershell
Get-Service *postgres*
```

В колонке `Status` должно быть значение `Running`.

Если служба остановлена, запустите ее через приложение «Службы» Windows или
pgAdmin.

## Первичная установка

Распакуйте архив и откройте PowerShell в папке `mebelorg_demo`.

Разрешите выполнение локального скрипта только для текущего окна PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

Запустите установку:

```powershell
.\setup.ps1
```

Пароль PostgreSQL уже указан в установочном скрипте: `postgres`.

Скрипт автоматически:

1. Проверит подключение к PostgreSQL.
2. Создаст базу данных `furniture_demo`, если ее еще нет.
3. Создаст файл `.env` с локальными настройками подключения.
4. Установит зависимости через `uv`.
5. Создаст таблицы с помощью миграций Django.
6. Загрузит данные из `data/csv`.
7. Подготовит изображения товаров.

После сообщения `Setup completed successfully` файл `setup.ps1` можно удалить.

## Запуск сайта

После установки выполните:

```powershell
uv run python src/manage.py runserver
```

После запуска откройте:

```text
http://127.0.0.1:8000
```

Для остановки сервера нажмите `Ctrl+C`.

## Нужно ли создавать базу вручную

Нет. При выполнении `setup.ps1` база создается автоматически:

```text
furniture_demo
```

Владельцем будет пользователь PostgreSQL:

```text
postgres
```

SQL-файл `database/schema.sql` вручную выполнять не нужно. Таблицы приложения
создаются миграциями Django.

## Если база создана вручную

В pgAdmin можно заранее создать пустую базу со следующими параметрами:

```text
Имя: furniture_demo
Владелец: postgres
Кодировка: UTF8
```

После этого выполните `.\setup.ps1`. Скрипт обнаружит существующую базу,
применит миграции и импортирует данные.

Стандартные значения:

| Параметр | Значение |
|---|---|
| База данных | `furniture_demo` |
| Пользователь | `postgres` |
| Пароль | `postgres` |
| Сервер | `localhost` |
| Порт | `5432` |

## Команды для демонстрации

Если нужно показать этапы работы отдельно:

```powershell
uv sync --frozen
uv run python src/manage.py migrate
uv run python src/manage.py import_demo_data
uv run python src/manage.py check
uv run python src/manage.py test furniture
uv run python src/manage.py runserver 127.0.0.1:8000
```

Назначение команд:

| Команда | Что делает |
|---|---|
| `uv sync --frozen` | Устанавливает зависимости из `uv.lock` |
| `migrate` | Создает и обновляет таблицы PostgreSQL |
| `import_demo_data` | Загружает нормализованные CSV-данные |
| `check` | Проверяет настройки Django |
| `test furniture` | Запускает автоматические тесты |
| `runserver` | Запускает локальный сайт |

## Частые ошибки

### `uv was not found`

Не установлен `uv` или его папка отсутствует в `PATH`.

После установки закройте и заново откройте PowerShell, затем проверьте:

```powershell
uv --version
```

### `Cannot connect to PostgreSQL`

Проверьте:

- запущена ли служба PostgreSQL;
- равен ли пароль пользователя `postgres` значению `postgres`;
- используется ли порт `5432`;
- разрешены ли локальные подключения.

### Выполнение сценариев отключено

Выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

Затем снова:

```powershell
.\setup.ps1
```

### Порт `8000` занят

Закройте другой локальный сервер или его окно PowerShell и повторите:

```powershell
uv run python src/manage.py runserver
```

### Стили не загрузились

Обновите страницу без кеша:

```text
Ctrl+F5
```

Также убедитесь, что команда запуска выполнена из корня проекта.
